# Quick start

## 1. Install

```bash
pnpm add -D iconctl
```

## 2. Create a config

```bash
pnpm exec iconctl init
```

Or write `iconctl.config.ts` yourself:

```ts
import { defineConfig } from 'iconctl'

export default defineConfig({
  prefix: 'brand',
  sources: [
    {
      type: 'figma',
      file: 'https://www.figma.com/design/<fileKey>/Icons',
      pages: ['Icons'],
    },
  ],
  output: {
    json: 'icons.json',
    svg: 'svg',
    preview: 'preview.html',
  },
  validate: {
    width: 24,
    height: 24,
  },
})
```

A local folder is the zero-token path and produces the same Iconify JSON:

```ts
sources: [{ type: 'directory', dir: './raw-svg' }]
```

## 3. Token

For Figma, use [OAuth login and automatic renewal](/figma#oauth-login-and-automatic-renewal). After configuring your app, run `pnpm exec iconctl auth figma login`; subsequent syncs refresh tokens automatically. Directory sources need no credentials.

Alternatively, use a personal token, which requires manual replacement:

```bash
export FIGMA_TOKEN=figu_xxx
```

## 4. Sync

```bash
pnpm exec iconctl sync
```

CI:

```bash
pnpm exec iconctl sync --json
```

`--dry-run` skips icon outputs but may update authentication and caches. Icon import, processing and validation failures exit non-zero by default and preserve the previous outputs. Errors identify the affected icons, including missing Figma exports and failed SVG downloads.

To explicitly allow partial outputs, use `pnpm exec iconctl sync --continue`. This command exits successfully and prints warnings for skipped icons and validation issues. With `--json`, inspect the existing `skipped` and `issues` fields to detect a partial result. Authentication failures and unreadable sources still stop the command.

Partial syncs do not mark a Figma revision as completed. After fixing the source or connection, run `sync` again to retry the failed icons. Invalid SVG responses and incomplete image export responses are not reused from the download cache.

All configured outputs are prepared before replacing existing files. Generation or replacement failures trigger rollback; if rollback cannot finish, the error identifies the retained recovery files. A cleanup failure after commit emits an `ICONCTL_OUTPUT_CLEANUP` warning with residual directories; the committed sync still succeeds. Output paths must be distinct and cannot contain one another: for example, place `icons.json` alongside the SVG directory, not inside it. The same rule covers JSON package directories, preview, types, changelog and cache metadata.

The SVG output directory contains an `.iconctl-manifest.json` that tracks generated SVGs. Later syncs remove obsolete generated files and preserve unrelated files. During the first cleanup after upgrading, legacy files are treated as generated only when their contents exactly match the previous Iconify JSON. Unrecognized obsolete files are retained; filenames generated by the current sync are still updated. Keep the manifest with the SVG output directory.

## 5. Use the JSON

With `@iconify/tailwind4` or UnoCSS, point a custom collection at `icons.json` and use `i-brand-arrow-left`. That class is a CSS mask, not a font.

Two ways to get the JSON to other developers: ship it **in the app repo**, or publish an **installable package**. See [Distribute](/distribute).
