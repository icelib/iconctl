# 私有线上控制台

[打开控制台](https://iconctl.icebreaker.top/app/)。公开文档不需要登录；控制台、业务 API 和产物下载仅向 GitHub 用户 ID `15621541`（sonofmagic）开放。

## 创建并安装 GitHub App

组织 Owner 打开 **组织 Settings → Developer settings → GitHub Apps → New GitHub App**。本项目使用 [icelib/iconctl-console](https://github.com/organizations/icelib/settings/apps/iconctl-console)。

- Homepage URL：`https://iconctl.icebreaker.top`
- Callback URL：`https://iconctl.icebreaker.top/api/auth/github/callback`
- Webhook URL：`https://iconctl.icebreaker.top/api/webhooks/github`
- Repository permissions：Contents、Actions、Pull requests、Workflows 均为 Read and write；Metadata 为 Read-only。
- Subscribe to events：Workflow run。
- 安装范围选择 Only on this account；创建后进入 **Install App → Install → Only select repositories**，只选择需要管理的仓库。

在 General 页面生成 Client secret 和 Private key。App ID、Client ID、Client secret、PEM 私钥分别写入 Worker Secrets：`GITHUB_APP_ID`、`GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`GITHUB_PRIVATE_KEY`。Webhook secret 使用独立随机值，同时填到 GitHub App 和 Worker 的 `GITHUB_WEBHOOK_SECRET`。

私钥用于签发 installation token；Client secret 用于网页登录，两者都需要。不要在网页保存 GitHub PAT，也不要把密钥提交到仓库。

## 连接 Figma / MasterGo

为站点创建独立的 Figma OAuth App，登记 HTTPS 回调：

```text
https://iconctl.icebreaker.top/api/auth/figma/callback
```

将 Client ID 和 Client secret 写入 Worker Secrets `FIGMA_CLIENT_ID` 和 `FIGMA_CLIENT_SECRET`。在「授权与插件」中点击「连接 Figma」，授权 `file_content:read`。本地 CLI、CI 和站点应使用不同 OAuth App 或账号。

access/refresh token 使用 AES-GCM 加密保存；独立的 `CREDENTIAL_ENCRYPTION_KEY` 为 32 个随机字节的 Base64。备份这个密钥，丢失后无法解密授权。浏览器只能查看状态。任务需要 token 时，距到期不足五分钟会续期；并发续期由 Durable Object 合并。Actions 通过 OIDC 只能领取当前任务来源的 access token，不会得到 client secret 或 refresh token。

断开后本地服务端凭据被删除；不代表 Figma 远端授权已撤销。刷新结果不确定或授权失效时，重新授权原连接。MasterGo 个人令牌同样加密保存，但不能自动续期。

## 项目与任务

1. 创建项目，填写已安装 App 的 GitHub 仓库、图标前缀和公开 npm 包名。
2. 添加 Figma、MasterGo、iconfont HTTPS Symbol URL、仓库 SVG 目录、仓库或上传的 Iconify JSON 集合，以及上传 SVG ZIP。即时设计使用导出 SVG。多个来源可以组合；后面的同名图标覆盖前面的图标。
3. 配置颜色、名称正则、尺寸、草稿前缀和输出选项。高级配置从固定 Git 提交读取 `iconNameForNode`，仅在 Actions 执行；来源、凭据、输出路径仍由任务固定。
4. 保存项目后，创建 runner 安装 PR，审查并合并到默认分支。控制台不会绕过分支保护。
5. 发起同步、仅校验、预览或 dry-run，在任务页面跟踪阶段、Actions 链接和快照。

上传限 10 MB ZIP，最多 5000 个 SVG，单个展开文件限 1 MB，总展开大小限 25 MB。拒绝绝对路径、目录穿越、非 SVG 文件及 SVG 来源中的符号链接。上传 ZIP 根目录在表单中使用 `svg`。图标以浏览器的 SVG image 模式展示；HTML 预览以附件下载，不在站点上下文执行。

ZIP 上传会在当前来源旁显示文件名和状态。同一时间只上传一个文件；完成或点击「取消上传」前，文件选择和项目保存保持禁用。失败后可点击「重试上传」重传同一文件，也可重新选择文件。替换已有上传时，新文件成功前保留原附件。上传本身不会保存项目或校验 SVG 内容，保存附件配置后再运行任务检查内容。

上传期间修改 ZIP 子目录，完成后会保留输入。移除来源、恢复使用仓库目录或离开该编辑会话会取消本地上传操作；迟到响应不会在其他编辑器附加文件或提示成功。取消导航确认时，上传仍在原来源继续。取消上传不会删除服务器已经收到的文件；供重试使用的文件只保留在当前编辑器内存中。

**Dry run** 和「仅校验」记录检查快照，但不写图标产物、不更新成功基线，也不能直接发版。认证凭据仍可续期。每个任务固定配置版本、源码提交及执行器提交。同一项目的任务串行，工作流还设置仓库级 concurrency 和 `cancel-in-progress: false`。

### 仓库或上传的 Iconify JSON

选择「Iconify JSON」，填写相对仓库根目录的路径，例如 `vendor/icons.json`。runner 从任务固定的源码提交读取文件，对应配置为：

```json
{ "type": "iconify", "file": "vendor/icons.json", "include": ["home", "arrow-left"], "namePrefix": "vendor-" }
```

默认「全部图标」会导入图标和别名。「指定图标」每行填写一个精确名称，忽略空行；名单留空会保存 `include: []`，不导入任何图标。名称前缀按原文拼接：`vendor-` 得到 `vendor-home`，`vendor` 得到 `vendorhome`，不会转换大小写或自动加分隔符。项目的草稿前缀过滤、颜色处理、尺寸／名称校验和输出配置继续生效。别名、旋转和继承尺寸使用与 CLI 相同的核心导入流程。

仓库文件入口无需来源凭据。文件必须是普通文件，大小不超过 25 MiB。拒绝绝对路径、目录穿越、Git 元数据、目录和指向仓库外部的符号链接；允许最终指向仓库内普通文件的链接。runner 在加载高级配置前，将检查后的字节复制到任务目录。JSON 语法或集合结构错误归类为配置错误；选中图标的问题写入校验快照并阻止发布。

也可以点击「上传 Iconify JSON（最多 10 MiB）」选择本地集合，无需先把 JSON 提交到 Git。项目仍须关联已安装工作流的 GitHub 仓库。上传成功后先保存项目，再运行任务。上传来源只保存 `upload` UUID，与 `file` 恰好保留一个：

```json
{ "type": "iconify", "upload": "00000000-0000-4000-8000-000000000001", "include": ["rotated-alias"], "namePrefix": "vendor-" }
```

10 MiB 限制针对原始 JSON 字节。上传检查严格 UTF-8（允许 UTF-8 BOM）、JSON 语法，以及字符串 `prefix`、对象 `icons`、可选对象 `aliases` 和字符串数组 `not_found`；原始字节和额外集合元数据完整保留。单个图标、变换、别名和项目规则由任务中的 core 校验，上传成功不等于校验通过。指定名单匹配添加 `namePrefix` 前的原始图标或 alias 键；选中的别名可以依赖未选中的父项，未选中条目的问题不会提前阻止本来有效的选择。

JSON 与 ZIP 共用一次一个上传的限制。替换成功前保留原仓库路径或附件，失败和取消不会丢失旧入口。JSON 上传期间禁用仓库路径输入；「恢复使用仓库文件」先取消待完成替换，再显示必填路径。移除来源、更换编辑会话或载入远端配置后，迟到回调不能重新附加旧文件。重试仅在原来源与原入口仍然有效时发送同一个选定文件。取消不会删除已被服务器接收的对象；当前没有上传过期时间或自动回收。

保存时检查 JSON 上传的格式与 R2 对象大小，提交前重新核对项目修订、活动任务和上传元数据。上传缺失或不可用时需重新上传并保存，不会自动回退到仓库文件。更换引用会增加项目修订，旧任务仍固定原 UUID；配置变化后须创建新任务。runner 只能下载冻结任务引用的对象，最多保留 10 MiB 字节，检查 MIME 与 SHA-256，再以固定任务内文件名写入，之后才执行高级配置。超限流块会在保留前拒绝，流中断不会留下部分输入。发布仍复用已确认快照，不重新读取来源上传。

API 使用 `POST /api/uploads?kind=iconify-json` 与 `application/json`；省略 `kind` 保持 SVG ZIP 行为。新记录保存 `kind`，旧记录缺失该字段时仅按 SVG ZIP 处理，两种格式不能交叉引用。格式错误返回 400，超限返回 413。管理数据与 R2 分开备份时，需保留两种格式的上传原始对象。

升级控制台后，先在各目标仓库创建并合并新版 runner 安装 PR，再启用此来源。工作流固定执行器提交；即使旧 runner 已支持仓库 `type: "iconify"`，JSON 上传仍需要对应新版执行器。

### 恢复工作空间加载

首次会话初始化或工作空间读取失败后，可点击「重新读取工作空间」，无需重新加载页面。会话尚未初始化成功或认证失败导致会话失效时，会重新建立会话；首次成功读取工作空间后即可操作项目。登录过期仍会跳转到登录页，并停止自动重试。若取消跳转后在其他页面重新登录，手动恢复会先获取新会话与 CSRF 令牌。

后续刷新失败时，控制台保留上次读取的工作空间，并显示更新时间；各视图都提供同一个重试入口。恢复会保留当前项目、草稿、任务筛选和键盘焦点，不会重新提交保存、任务、设备撤销或其他已成功的写入。成功写入后的读取必须重新开始，较早的轮询结果无法恢复写入前的状态。

自动读取每次只执行一轮，正常情况下在上一轮结束 10 秒后再次读取。每轮会话／状态读取在 30 秒后超时；暂时失败时按 10、20、40、最多 60 秒退避，成功后恢复正常间隔。手动重试可跳过等待。页面隐藏或写入尚未结束时暂停自动读取，返回页面或浏览器发出网络恢复事件时，在条件允许下合并为一次补充读取；保存后的显式读取仍可执行。离开控制台会取消待完成读取与定时器，迟到响应不会更新新会话或让它跳转登录。

### 保存项目配置

保存会固定当前项目、配置内容和修订号。请求期间可以继续输入或切换页面，后续修改仍显示为未保存；其他编辑会话的迟到结果只更新项目列表，不切换当前项目或覆盖草稿。新建项目只在原编辑器中接纳服务器分配的 ID，下一次保存会更新该项目，避免重复创建。

有未保存修改时，切换项目、离开编辑器、定位任务或退出登录会先要求确认。「继续编辑」或 Escape 保留完整草稿，并将焦点还给原导航控件；「放弃修改并继续」才执行目标导航。再次点击当前「项目配置」不会重置草稿，新建项目也一样。没有修改或已改回保存内容时，直接导航。

确认框打开后，保存仍可能完成。若没有后续修改，按钮会变为「继续前往」，但仍等待你决定；离开不会取消已提交的保存或任务。成功任务若会打断未保存的编辑，会保留「定位任务」入口。刷新、关闭标签页或在当前标签页打开链接时，在浏览器支持的情况下使用标准未保存提示；保存或撤回全部修改后移除保护。草稿只保存在当前页面内存中，离开后不能恢复。

保存成功后，即使工作空间刷新失败，已保存的结果也会保留。「重新刷新工作空间」只重试读取。服务器配置变化或保存冲突时，当前草稿保持完整，需要明确恢复后才能再次保存：「载入最新配置」会读取服务器状态并替换草稿。仍在执行的任务或已发布项目的身份限制可能继续阻止保存；恢复不会自动重试写入。

需要在保留本地修改的同时查看服务器新版本时，可点击「核对并保留草稿」。控制台只读取最新项目，并比较编辑基准、当前草稿和服务器配置。九个顶层分组（`name`、`repository`、`prefix`、`packageName`、`sources`、`color`、`validate`、`output`、`advancedConfig`）按整组处理；对象键顺序不会制造差异，`sources` 数组顺序会保留。某分组在本地和服务器都改过且值不同，必须明确选择「保留我的修改」或「采用服务器配置」。核对过程只读。「应用到草稿」只修改当前页面内存，将服务器修订号作为新的编辑基线，并继续显示未保存；之后点击「保存项目」才会执行原有的修订号、任务锁、来源引用和已发布身份检查。草稿在读取后发生变化、观察到更新的修订号、项目从工作空间消失或仍有上传任务时，当前核对不能应用，草稿会保持不变。「载入最新配置」仍然提供整份替换草稿的原有路径。

服务器在检查仓库后重新核对最新配置修订、任务锁、来源引用和已发布身份限制。检查期间完成的同步或发布会保留最新快照与发布基线。已发布项目不能更改项目名、npm 包名或仓库。

### 查找任务

在「任务与版本」中，组合任务状态、操作和关键词筛选当前项目的任务。关键词匹配任务 ID、源码 SHA、Actions run ID、当前阶段或错误，以及对应的展示文字。搜索忽略大小写和首尾空白，标点按字面匹配，例如 `[name]` 不会作为正则表达式执行。计数展示「匹配数 / 当前项目任务总数」，没有任务与没有匹配结果会分别提示。

自动轮询、点击「刷新状态」、打开快照后返回都会保留筛选条件。切换项目会清除条件。创建或重试任务成功时，如果仍停留在原操作上下文且没有未保存的项目修改，会清除筛选并聚焦返回的任务；若等待期间已切换项目、页面或筛选，或定位会丢弃草稿，则只记录任务，点击「定位任务」才切回对应记录。发布确认仍有效时也遵循相同规则。操作被拒绝时保留条件。筛选不改变项目执行锁或已发布版本列表。

通过 `?job=...` 打开的链接会自动选择所属项目并聚焦任务一次，后续刷新不会重新抢占键盘焦点或项目选择。切换项目、视图或筛选后若隐藏了链接任务，可点击「定位链接任务」恢复所属项目并清除筛选。不可用的链接会显示错误。

筛选在浏览器中处理 `/api/state` 返回的完整任务列表，不会分页或减少 API 响应量。下文的 500 条上限针对单个任务的阶段历史，不限制任务数量。

### 失败重试

重试保留任务 ID 和历史事件，并开始新一次执行（attempt）。同步、仅校验、预览和 dry-run 的每次执行各自拥有独立快照。旧快照仍可查看，但新一次执行不能复用旧快照内容，也不能接受上一轮 runner 迟到的结果。同一次执行重复提交相同结果是安全的；提交不同结果会被拒绝。

旧快照没有 attempt 字段时按首次执行处理，旧格式的快照预留记录也只属于首次执行；无需迁移即可继续读取。Runner 请求格式保持兼容，服务端根据当前 attempt 和已领取任务的 GitHub workflow run 绑定结果。已经准备好发布产物的任务重试时，继续复用原先确认的快照、tarball 和提交。

### 按尝试查看历史与诊断

在「任务与版本 → 尝试与快照」中，查看每次尝试的阶段、错误、Actions 执行记录和不可变快照。重试后旧快照仍有入口，当前尝试显示在最前面。每个任务最多保留最近 500 条阶段事件；快照独立保存。发布重试复用已确认的快照，仍可通过任务结果中的「查看快照」打开。

快照诊断展示失败阶段、来源类型与序号，以及已记录的设计节点。Figma 问题同时包含文件与节点标识时，可以点击「在 Figma 中定位」。来源序号从 1 开始。问题计数与发布阻止条件保持原有语义。

审核页还会显示随快照保存的不可变来源记录，包括来源序号、类型、可用时的文件标识，以及是否复用了未修改来源。缺少来源记录的旧产物仍可审核，并明确标为未记录；页面不会从当前项目配置反推历史来源。

旧快照缺少 `attempt` 时属于第一次尝试。没有尝试号的旧阶段事件单独列为「旧阶段记录（未记录尝试号）」，不推测归属。旧问题仍可读取，缺失的阶段或来源显示「未记录」。新增字段均可选，无需数据迁移或更改 runner 请求格式。结构化诊断需要任务固定的执行器提供相应字段；部署支持这些字段的执行器后，更新 runner 安装配置。

控制台展开历史后按需调用 `GET /api/jobs/:id/history` 读取更早的尝试。接口返回有上限的一页和绑定任务及项目的加密不透明游标；客户端只能原样回传游标，不能自行拼接。现有 `/api/state` 响应保持兼容，每个任务最多保留 500 条阶段事件。缺少 `attempt` 的旧快照在投影中归入第 1 次尝试，没有尝试号的旧事件仍单独保持未分配。游标缺失、篡改或过期会被拒绝，且不会修改任务或快照状态。

### 筛选诊断与复制单条定位信息

「问题阶段」和「问题来源」共同筛选问题列表。选项数量始终按完整快照计算，区域同时显示完整问题数、处理失败数和当前可见问题数。来源按已记录的类型与序号区分，同为 Figma 的 #1、#2 不会合并；`validate` 与 `validation` 共用「校验」，未知阶段仍可选择，缺少元数据时明确显示「未记录」。「清除诊断筛选」只重置这两个选择。处理失败名称没有已记录的阶段或来源，始终在独立分组中完整显示。筛选不会改变发布资格、SVG ZIP 或完整 JSON/HTML 比较报告。

每条问题与失败名称都有「复制定位信息」。确定性的文本以 `iconctl diagnostic location v1` 开头，记录项目、快照 ID 与摘要、生成任务、快照尝试号、记录类型和原数组从 0 起算的索引。问题只附加原始名称、错误文字及已记录的阶段、来源、设计节点字段；失败记录只附加名称。所有值均以 JSON 标量编码，保留引号和换行，来源索引仍从 0 起算。可用的 Figma 文件与节点字段生成和行内相同、固定域名的设计链接。文本不包含当前任务状态、项目配置、凭据、已存文件或 SVG body；整条信息超过 16 KiB UTF-8 时直接拒绝，不截断记录。

定位身份始终属于当前显示的不可变快照，任务后来重试成功也不会改写旧失败尝试。旧快照未记录尝试号时按 1 处理；显式无效的尝试号会禁用复制并说明原因。切换快照加载中或失败时保留原诊断与筛选，加载期间暂停筛选和复制；新快照成功提交后重置筛选与复制反馈。仅修改同一快照的比较基准会保留筛选，但每次新比较请求都会清除复制反馈。工作空间轮询不会重置筛选或焦点。

只有明确点击才会写入剪贴板，请求发给浏览器后无法真正取消。同一时间所有行与视图共用一个未完成写入，直到浏览器返回；迟到回调不会恢复旧反馈。写入等待期间仍可点击「显示定位文本」，该路径不调用剪贴板 API。浏览器不支持写入或拒绝权限时也会提供只读文本；点击「选择定位文本」后使用 Ctrl/Cmd+C 手动复制。异步失败不会移动焦点，离开页面会清理手动文本。这些操作不会创建任务、保存状态或向外发送诊断。

### 追溯快照的生成尝试

审核页的「快照来源」显示生成任务、操作与尝试号，以及任务创建时固定的项目名称、配置修订、仓库和源码提交。项目后来修改、任务重试或发布复用快照时，这些字段仍属于生成当前快照的任务。Actions 链接只取明确记录了同一尝试号的阶段事件；事件缺失或超出保留范围时，页面会说明未记录对应执行链接。

点击「定位生成任务」后，控制台选择所属项目、清除任务筛选，在「任务与版本」中展开并聚焦准确的尝试。即使任务已在第二次尝试成功，第一次的旧快照仍会回到第一次。定位只执行一次，后续工作空间刷新不会重新展开或抢走焦点。切换快照尚未完成或请求失败时，来源区域始终与正在显示的审核内容一致。

生成任务缺失或项目身份不匹配时，显示「来源任务暂不可用」；仅当前项目缺失时，历史来源仍可查看，定位按钮禁用。这两种情况都不影响读取快照，可点击「重新读取工作空间」刷新关联。旧快照仍按首次尝试处理，没有尝试号的旧事件不会被用于猜测对应执行记录。本功能无需修改 API 或迁移持久化数据。

### 下载离线比较报告

在审核页点击「下载比较 JSON」供脚本读取，或点击「下载比较 HTML」离线查看与打印。报告包含全部新增、修改、删除图标的前后图像数据，以及当前快照的全部问题和处理失败名称。搜索与状态筛选不会裁剪报告。报告不包含未变化图标或已存产物文件；零增删改也可生成报告，仅 prefix 变化时会单独提示命名空间改变。

报告只使用当前已提交的审核响应，包括快照 ID、摘要、尝试号，以及实际比较基准快照和发布版本。原始上次同步基准可能与所选发布或指定快照不同。首次发布与无历史同步都明确标为和空集比较。切换比较正在加载时暂停下载；选择失败后，可下载仍保留的审核内容。切换快照、基准、项目或页面会取消未完成的生成，后续工作空间刷新不会改写报告基准。

JSON 使用 `format: "iconctl-console-comparison"`、`schemaVersion: 1` 和 `scope: "changes"`。`snapshot`、`comparison` 标识审核的两侧，`prefixes` 记录命名空间变化，`diff` 原样保留 API 的 `added`、`changed`、`removed` 名称数组。`icons` 的每项包含名称、分类和可为空的 `before` / `after`，每侧仅保留原 SVG `body` 与有效 `width` / `height`（依次取图标、集合、缺省 16）。`diagnostics` 保留全部问题和失败名称；已有 `sourceIndex` 仍从 0 起算。未知扩展元数据、项目配置、连接、凭据、来源配置及 `content.files` 不会复制进报告。这是有格式版本的审核记录，不是可导入的 Iconify 集合或备份。

分类严格沿用在线 API 结果。仅元数据发生变化时，即使前后图像相同，条目仍可能属于「修改」；导出不会重新运行 CLI 差异算法。HTML 是无需脚本或外部资源的独立文档，SVG 只放在隔离的数据图片中，所有元数据都按文本转义。下载后用浏览器打开，再使用浏览器打印功能即可，全程无需联网。

生成限制为最多 5,000 条变化、问题与失败名称合计 5,000 项、单个 SVG body 的 UTF-8 不超过 512 KiB、所选文本合计不超过 4 MiB、最终单个文件不超过 8 MiB。超限或比较数据不一致会让本次导出整体失败，不截断记录。这些限制只针对报告生成，不限制已经载入内存的 API 响应。错误显示在下载按钮旁，解决原因后再次点击即可重试。同一响应生成的报告内容确定；下载不会创建任务、发布图标或保存控制台状态。

## 确认并发布

同步生成不可变快照。预览默认显示相对上次成功快照的新增、修改、删除及前后对比。将「比较基准」切换为「最近发布」，即可查看多次同步后相对已发布版本的累计变化；也可以选择同项目的任意快照。页面显示实际使用的基准，切换比较不会修改快照；校验问题会阻止发布。

只有最后一次快照或比较选择能更新审核内容。加载期间保留上次审核的快照、比较和下载链接，并暂停发布；请求失败时保留这组内容并在审核区域显示重试提示。切换项目或离开审核页会取消未完成的读取，迟到响应不会带你回到旧项目。

选择 patch / minor / major 后，控制台显示实际包名、目标版本、图标数量、快照摘要，以及相对本次确认锁定的发布版本的累计新增、修改和删除。发布确认始终按发布基准计算，不受预览页所选基准影响。首次发布按空图标集比较，全部图标记为新增，版本为 `0.1.0`。准备确认期间若项目配置、发布版本发生变化，或有其他任务启动，需要重新审核；确认后的发布基准变化也会阻止提交。点击确认才创建发布任务；它复用这一快照和 npm tarball，不重新抓取 Figma。

发布错误直接显示在确认对话框中。确认过期、丢失或失效时，点击「重新获取发布确认」，检查新版本与差异后再次明确确认；重新预览不会自动发布。若项目配置已经变更，需要先选择修订匹配的新同步快照。网络或网关异常后，「重试发布请求」沿用同一确认和幂等键，已创建的任务会直接返回，不会重复创建。请求未完成时也可以返回审核；如果之后收到成功结果，控制台会保留任务并提供「定位发布任务」入口，不切换当前项目或页面。

产物提交到 `iconctl/<项目名>` 专用分支，公开发布到 npm `latest`，然后创建 `<项目名>/v<版本>` tag 和 GitHub Release。分支基线或版本发生外部变化时停止，不强推。npm 已成功但回调丢失时，alarm / webhook 对比 registry 的 `dist.integrity`，补齐记录。失败重试复用原 tarball；不要手工删除未对账的任务。

### npm 首次发布与可信发布

新包可在目标仓库配置 `NPM_BOOTSTRAP_TOKEN` Actions Secret：使用具备目标包发布权限的 npm granular token，按 npm 要求允许自动化发布。网站不保存这个 token，只有发布步骤能读取它。

包创建后，在 npm 包设置的 Trusted Publisher 中选择 GitHub Actions，填写目标 owner/repo 和工作流文件名 `iconctl-console.yml`。**明确启用直接 `npm publish` 权限**：新建 Trusted Publisher 的默认设置可能只允许 `npm stage publish`。使用 GitHub-hosted runner、Node 24、npm 11.5.1 以上。配置就绪后删除 `NPM_BOOTSTRAP_TOKEN`，后续使用 OIDC / provenance。

项目包与 iconctl 仓库本身的发布流程独立，不在这里修改 monorepo 包版本。

## 部署、回滚与恢复

Console CI 工作流在 pull request 和 main 上使用 Linux、Node 24，依次构建控制台与 runner、检查类型、运行 runner/contracts 测试和独立的 Cloudflare Worker 测试，再通过 Chromium 验证浏览器流程。Worker 测试使用 console 自己的 Vitest 版本，不包含在根目录 `pnpm test` 的项目列表中。浏览器截图和失败 trace 会保留为工作流产物。

GitHub 登录与目录来源可先上线；未配置站点专用 Figma App 时，连接 Figma 会明确提示配置缺失。配置 `FIGMA_CLIENT_ID` 和 `FIGMA_CLIENT_SECRET` 后即可启用，无需填写占位凭据。

统一入口位于 `apps/console/wrangler.jsonc`。Vue 输出和 VitePress 文档合并到同一个 Worker，文档原 URL / 404 行为保持。原 website 的部署命令也转发到 console，避免静态站部署覆盖后端。

```bash
pnpm exec turbo run build --filter=@iconctl/console... --filter=@iconctl/console-runner...
pnpm --filter @iconctl/console exec wrangler r2 bucket create iconctl-console-production
# 使用仓库之外、权限为 0600 的 JSON 文件导入；内容包含上述八项 Secrets。
pnpm --filter @iconctl/console exec wrangler secret bulk /absolute/path/production.secrets.json --env ""
pnpm --filter @iconctl/console run deploy
```

控制台构建先完成类型检查及完整 Website 输出预检，再重建自有的 `apps/console/dist/public` 目录，随后把当前 Vue 应用写入 `app/` 并复制完整文档。因此页面和公开资源删除、改名后不会继续残留。请使用上面的命令先构建依赖；单独执行控制台构建时，需要已有当前 Website 产物。内部组装脚本根据脚本位置解析固定目录，要求 Website 具有普通文件 `index.html`，拒绝文档产物及复制目标中的符号链接、拒绝链接形式的 `dist`/`public` 输出目录，并为应用保留 `app`、`api`、`login` 及其 `.html`、大小写变体。自编文件应放在源码或 public 输入目录，不放在生成目录。类型检查或输入预检失败会保留当前输出；准备完成后的失败可能留下不完整产物，只有构建成功后才能部署。`pnpm --filter @iconctl/console test:build` 使用 Node 原生测试运行器验证独立输出夹具，Console CI 将其与 Worker Vitest 分开执行。

部署要求改动已提交且提交已推送到 `origin/main`，执行器固定到该 SHA；脚本先执行 dry-run 再部署。GitHub 自动部署需配置 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` Secrets，并在初次接入验证后设置仓库变量 `ICONCTL_DEPLOY_ENABLED=true`。创建 GitHub production environment 可进一步管理部署访问。

仓库保留可选的独立 staging 配置（独立 DO 和 R2）。本实例按所有者选择直接使用 `iconctl.icebreaker.top`；真实 Figma OAuth 与 npm 发布仍需要完成提供方配置后验收。每次更新执行器后，目标仓库需重新创建并合并安装 PR。

```bash
pnpm --filter @iconctl/console exec wrangler versions list --env ""
pnpm --filter @iconctl/console exec wrangler rollback <previous-version-id> --env ""
```

在「授权与插件」下载加密管理数据备份，并使用具备 R2 访问权限的工具备份私有 bucket 的全部对象（含 snapshots、uploads、releases）。将加密密钥与备份分开保管。恢复时先停止派发任务，恢复到空的独立环境，使用同一加密密钥，在「授权与插件 → 恢复到空账户」导入管理备份并恢复 R2 原始对象 key，再核对快照摘要与 registry 完整性。旧 Figma 授权可能已旋转，恢复后重新授权；插件重新配对；未完成发布先对账。通过验证后切换绑定。不要将数据库回滚当作 npm 撤包。

### 插件项目预检与任务恢复

连接控制台后，Figma 插件使用项目配置的宽高、命名规则与草稿前缀；未设置的尺寸不受限制。高级命名 hook 仍由固定版本的 runner 校验，插件会明确提示。每次新同步前刷新规则；预检后配置发生变化时，需要检查新规则并再次点击同步。旧 GitHub 模式继续使用 24×24 预检。

使用默认命名时，当前页中归一化后名称相同的组件（例如 `Arrow Left` 与 `arrow_left`）都会标为 **Duplicate icon name**，组件集变体也参与检查；修正名称并重新扫描前不能提交新任务。可通过 **Problems only**、搜索、**Locate** 和完整 JSON 报告查看每个冲突组件。被规则跳过的草稿不参与检查；高级服务端命名结果尚未确定，不会因本地名称相同而提前阻止提交。检查范围仅为当前页，完整同步范围仍需服务端校验。已提交任务继续跟踪，不会因当前页出现错误而中断。

点击预检结果旁的 **Locate**，即可在 Figma 画布选中并显示对应组件。两种连接模式都支持定位有错误的组件及组件集内的变体；被预检规则跳过的草稿不显示定位按钮。修正组件后点击 **Rescan** 更新结果。切换页面会禁用旧页面的定位按钮，重新扫描后恢复；组件已删除或移到其他页面时会提示重新扫描。定位只调整画布选区和视野，不修改组件内容或服务端配置的同步范围。

使用 **Search preflight** 搜索节点 ID、原始名称、最终图标名或问题文本，再用 **Problems only** 只看错误。搜索不区分大小写，按字面匹配，可与问题筛选叠加。列表显示匹配数与总数，**Clear filters** 恢复完整列表。筛选不改变检查或提交范围：被隐藏的错误仍会阻止同步。重新扫描会保留筛选条件；切换筛选会取消尚未完成的定位，当前扫描仍可用于定位可见行。

开启 **Live preflight** 后，编辑当前页即可自动重新预检。开关默认关闭，仅在本次插件会话有效，不写入存储。插件收到页面编辑事件时，会立即暂停旧扫描的定位、报告和提交；连续 150ms 没有新编辑后，使用已加载规则重新扫描整页。搜索、Problems only 和 Issue type 保持不变，问题位置随新扫描重置。嵌套节点增删、组件集名称、草稿前缀和重复名称同样会重新检查。

实时预检不会读取远端规则、保存设置、提交任务、触发 GitHub Action 或下载报告，已有任务继续跟踪。规则读取期间，实时预检和手动 Rescan 均等待当前请求；读取失败后需点击 **Refresh project rules** 恢复。恢复已有设备但尚未成功加载规则时，预检保持不可用，不会退回未配对默认规则。切换页面或模式会保留开关并使用新上下文；重新配对、断开、凭据撤销或关闭插件会关闭开关。关闭开关会取消待处理扫描，已经失效的结果仍需 Rescan；扫描错误可在再次编辑或手动 Rescan 后恢复。仍需服务端校验，已经下载的报告保留为历史快照。

使用 **Previous problem** 和 **Next problem** 可依次定位当前筛选列表中有错误的组件；同一组件有多条问题时只计为一项。Next 从第一项开始，Previous 从最后一项开始，到达末尾后循环。位置指示最近请求定位的组件；组件已删除或移动时，可继续下一项或重新扫描。对有错误的行点击 **Locate** 也会更新位置；更改筛选或重新扫描会重置位置。每行显示节点 ID，可从 JSON 或 HTML 报告复制 ID 到搜索框找到组件。可用键盘聚焦按钮后按 Enter 或空格操作，不影响任务跟踪或提交规则。


使用 **Issue type** 可集中查看 Naming（命名）、Canvas size（画布尺寸）或 Duplicate names（重复名称），并与搜索、Problems only 取交集。All issue types 不额外缩小范围，关闭 Problems only 时仍显示健康组件。数量按完整扫描中的组件计算，不受当前筛选影响；同一组件可属于多个类别，但每类只计一次，草稿不计入。**Other** 包含旧插件的未分类问题、未知诊断代码或不完整分类数据，原始问题文本始终保留。

问题类别只在本次会话中保留，Rescan 与 Live preflight 会沿用选择。所选类别没有匹配项时仍保持选中并显示空态，Other 的最后一个问题解决后也是如此。**Clear filters** 同时清空搜索、Problems only 和类别。更改类别会取消进行中的 Locate、重置上/下问题位置，保留当前扫描、任务跟踪和进行中的报告或 SVG 下载。隐藏的错误仍会阻止新同步与 SVG 交接；JSON/HTML 报告和 SVG ZIP 均保留完整当前页范围。整页健康时，即使筛选列表为空也仍可导出。

使用 **Sort components** 可按 **Page order**、**Local name** 或 **Original name** 排列当前筛选列表。本地名称按捕获的原值比较，空或缺失的名称放在最后；比较区分大小写并遵循 JavaScript 字符顺序。名称相同时依次使用原始名称、节点 ID 和捕获时的页面顺序作为稳定排序。排序只影响当前列表以及 Locate、问题导航和 Select visible components 发出的顺序，不会修改扫描快照、报告或 SVG/任务输出，不保存偏好，也不改变选区集合。排序会清除导航和复制反馈，已经开始的剪贴板写入仍会完成。选项仅在当前插件会话有效，会在重扫和实时预检后保留。

JSON 预检报告继续使用 `schemaVersion: 1` 和原有 `issues` 字符串，只在图标项上可选增加 `diagnostics`，每项仅含 `code`、`message`。当前检查代码为 `name-rule`、`canvas-size`、`duplicate-name`，按顺序对应同索引的原问题；未知代码也保持可读。缺失或不一致的分类数据在报告中省略，在插件里归为 Other。提交资格始终以原问题为准，旧消费者仍可读取不含 diagnostics 的报告。HTML 报告保留原有问题文字和完整捕获扫描。

**Problems only** 会在关闭重开后恢复，搜索文字仅保留在当前会话。GitHub 设置和视图偏好分别恢复，不会覆盖已经编辑的字段。本地存储失败时可使用对应的 **Retry** 按钮，当前会话与任务状态仍可使用；重试保存会采用当前值。重新构建私有插件即可使用这些控件，无需更新服务端或迁移数据。

展开 **Applied rules** 可查看当前扫描实际采用的项目名称与修订号、尺寸（未限制时显示 Unrestricted）、命名规则、跳过前缀和服务端命名提示。显式空前缀列表显示 None。概览与导出报告对应同一次扫描，GitHub 旧版默认规则和未配对默认规则会单独标明。

已连接且空闲时，点击 **Refresh project rules** 会读取一次最新项目规则并重新扫描当前页；不会提交或恢复保存的任务，原任务状态和 Open task 链接保持可用。刷新期间，旧结果不能用于提交、导出或定位。读取失败后可再次点击重试，Rescan 或切换模式不能重新启用过期项目规则。规则接口不可用（404）时保留设备关联和任务记录以便重试；凭据撤销后需要重新连接。GitHub 模式仍可独立使用旧版默认规则。配对或任务跟踪期间不能刷新规则，重叠请求会收到明确的忙碌提示。本地预检通过后仍需服务端校验。

点击 **Export JSON report** 下载最近一次成功扫描的完整当前页报告，包含草稿、有错误的图标和被筛选隐藏的结果；空页面扫描也能导出。报告记录扫描时间、页面、原始名称与本地计算的图标名、节点 ID、尺寸、问题、汇总及实际使用的规则；已连接的扫描还包含项目名称和修订号。报告不包含设备凭据、GitHub 设置或任务状态，导出不会提交任务或上传内容。

点击 **Export HTML report** 可下载独立 HTML 页面，离线阅读或打印。HTML 与 JSON 来自同一次完整扫描，保留全部组件、草稿、问题和实际规则；可用浏览器“查找”定位名称或节点 ID。文件不含脚本、外部资源或嵌入 SVG，组件文字会转义显示。两种格式共用扫描时间与失效规则；导出期间两个按钮暂时禁用，下载失败后可重试。插件只保存文件，不自动打开浏览器标签页。

报告仅表示当前页的本地预检，仍需服务端校验；使用服务端高级命名 hook 时，本地图标名是临时结果。重复导出保留同一次扫描的时间与内容；编辑组件后应重新扫描。切换页面或模式、变更项目连接以及扫描失败都会使旧报告失效。扫描失效后，也会暂停提交，直到新扫描成功。即使错误阻止提交，仍可导出报告；下载失败时可以显式重试，不改变筛选条件或工作流状态。重新构建插件即可使用，无需修改服务端或迁移存储数据。

插件会先保存提交标识再发送请求。关闭重开、响应丢失或断网恢复时，会恢复同一任务，不重复提交。轮询持续到服务端报告完成或失败，支持超过二十分钟的任务。断开或重新配对会结束旧的本地跟踪；在控制台撤销设备会同时收回服务端权限。任务链接自动选中所属项目并定位记录，无效链接会明确报错。

请先部署新版控制台，再更新插件。项目上下文接口仅返回项目展示信息、修订号及预检规则；服务端继续兼容旧插件，但旧插件无法执行新增的规则修订检查。

在快照的下载产物区域点击「下载全部 SVG」，即可把当前快照中已保存的 SVG 打包为一个 ZIP。搜索、差异筛选和比较基准不会缩小下载范围。文件路径和字节保持原样，包括子目录；部分名称能否解压取决于本地操作系统。ZIP 不包含 HTML 预览或其他产物，下载也不会重新校验、抓取来源或发布包。失败快照中已保存的 SVG 仍可下载，原有诊断与发布限制保持不变。

ZIP 下载支持最多 8 MiB 的快照文档、5000 个 SVG、单文件 1 MiB、SVG 总大小 5 MiB，文件使用不压缩的 ZIP 存储方式。超出范围时仍可逐个下载产物。仅校验、dry-run 或关闭 SVG 输出等没有已存 SVG 的快照不提供 ZIP。

下载进度和错误显示在当前快照旁，失败后再次点击按钮即可重试。切换快照、比较基准、项目或离开预览会取消未完成的下载，迟到响应不会替其他预览发起下载。「已发起下载」表示下载已交给浏览器，不代表文件已保存到本地。

### 下载完整快照集合

在下载产物区域点击「下载完整 Iconify JSON」，保存当前审核快照的完整 `content.json` 集合。没有生成文件的 check/dry-run 快照、空集合和历史失败 attempt 均可下载。搜索、差异或诊断筛选以及比较基准不会缩小集合，也不会改为下载基准快照的图标。原有诊断继续显示；失败快照可能只包含当次可用图标，下载不代表校验通过。

导出保留集合已有字段和元数据，不重新加工 SVG、改名或插入 snapshot/issues 字段。它是任务处理后的集合，不是来源上传文件或设计原始字节。JSON 序列化可能改变空白，与生成的 `files/icons.json` 不保证逐字节相同。现有 `/api/snapshots/:id/files/icons.json` 链接仍返回原文件字节；界面用完整集合按钮替代重复入口。JSON/HTML 比较报告仍是独立审阅文档，SVG ZIP 仍要求快照中已有 SVG 文件。

`GET /api/snapshots/:id/icons.json` 需要 owner 会话和快照 UUID，核对存储文档摘要及 **25 MiB 文档上限**后，下载 `iconctl-icons-<快照 UUID>-<文档摘要前 12 位>.json`。名称标识快照文档，该摘要不是导出文件本身的 SHA-256。元数据或存储缺失返回 404，无效 UUID 返回 400，无效/不匹配摘要或损坏集合返回 409，文档超限返回 413。响应使用 JSON、private no-store 缓存策略和 sandbox CSP。下载不创建任务或快照，不修改项目或发布状态。

JSON 与 SVG 下载各自显示进度。比较加载期间不可下载；切换快照、比较基准、项目或离开审核会取消旧请求，失败后需显式重试。已交给浏览器的下载无法撤回；「已发起下载」不代表文件已保存。合法导出集合可交给本地 `iconctl preview --input`、`iconctl diff` 或 `iconctl sprite --input`；每个命令仍执行各自的校验与格式限制。

### 选择当前可见组件

点击 **Select visible components**，用搜索 × Problems only × Issue type 的当前列表替换 Figma 画布选区，草稿不计入。「可见」指插件筛选列表，不是画布视口或图层显隐状态。操作保留画布缩放和中心；聚焦单个组件仍可使用 Locate 或上/下问题。它不会修改内容、改名、移动、解锁或取消隐藏。

选择范围来自最近一次已接受扫描，命名、尺寸、重复名称错误、缺失本地名称及服务端临时名称均可选择。关闭 Live preflight 时，编辑后请先 **Rescan**。空视图不会清空当前选区。每次最多 **500 个组件**，超限需缩小筛选；这是 iconctl 的操作限额，不是 Figma API 上限。缺失、重复、草稿或过期 ID 会整次拒绝，不选择部分结果。

宿主串行读取节点，全部完成后再次核对每个组件的身份和当前页归属，才执行一次选区赋值。节点已删除、移页，或变成同组选中项的祖先/后代时，需 Rescan 后重试。等待检查期间手动改变画布选区会取消本次操作；新的 Locate、上/下问题或选择请求会接管。筛选、重扫、页面/模式/项目规则变化与关闭插件都会丢弃旧请求。Figma 的选区事件异步送达，因此这不构成原子文档快照。原生赋值无法确认完整结果时，插件会报告失败，不自动回滚或重试；请先检查画布选区。

报告、SVG 交接、任务跟踪和名称复制保持原有范围与生命周期。选择筛选子集不会缩小整页报告、SVG 导出或同步资格。这是本地宿主操作，不发网络请求、不保存偏好。重新构建插件即可使用，无需更新服务端或迁移报告格式。

### 复制当前视图的本地名称

点击 **Copy visible names JSON**，复制最近一次已接受预检中搜索 × Problems only × Issue type 的可见结果，草稿不计入。**Clear filters** 恢复整页非草稿范围。复制不会重新扫描；关闭 Live preflight 时，编辑后请先 **Rescan**。扫描失效或项目规则仍在读取时，需先刷新有效结果。

JSON 数组保留现有本地 `iconName`，去重后按字符顺序排序并添加结尾换行，不再规范化。组件数与唯一名称数会显示合并了多少重复项。命名、画布尺寸或重复名称错误仍可复制供审阅；任一可见组件缺名或空名时整次拒绝，不复制部分名单。空视图不会把剪贴板替换为 `[]`。上限为 5000 个可见组件及 1 MiB UTF-8 JSON，超限不截断。

这些是本地预检名称。配置了高级命名 hook 时，此处名称仍是**临时结果**，确认名称请使用控制台快照。复制内容不添加前缀、扩展名或来源配置。Iconify 的 `include` 匹配输入 JSON 在 `namePrefix` 处理前的原始键，使用前需核对；Figma 使用 `pages`/`ids`，directory 来源也没有名称 `include` 配置。

自动剪贴板访问取决于 Figma 的浏览器环境。API 不可用或被拒绝时，插件显示完全相同的只读 JSON；点击 **Select JSON** 后按 Cmd/Ctrl+C。失败不会抢走键盘焦点或自动重试。筛选变化、新扫描或扫描失效会清除手动文本和复制反馈。原生写入同时最多一笔；视图改变或插件关闭后，已经开始的写入仍可能把当时捕获的名单写入剪贴板，请等待结束后再显式复制新视图。

复制会保留正在进行的 Locate、问题导航、任务跟踪、报告及 SVG 导出。报告与 SVG 继续使用完整当前页及原有资格，隐藏的错误仍然有效。复制不新增宿主消息、网络请求、任务或存储写入。重新构建插件即可使用，无需更新服务端或报告格式。

### 复制当前视图的节点 ID

在 **Copy JSON content** 中选择 **Figma node IDs**，点击 **Copy visible node IDs JSON**，即可交接当前筛选组件的 ID；本地名称缺失、非法、重复或仍待服务端确认时也可使用。默认仍为 Local names。两种内容均来自最近一次已接受扫描，排除草稿；复制不会重扫、改变画布选区或缩放。

ID 原文按字符顺序排序为 JSON 数组，并保留结尾换行。任一 ID 缺失或重复时整次拒绝；空视图、超过 5000 个组件或 1 MiB UTF-8 JSON 都不会截断复制。这是复制功能的限制，不代表 Figma REST 请求上限。请在原 Figma 文件中使用这些 ID，例如：

```ts
{ type: 'figma', file: 'https://www.figma.com/design/FILE_KEY/Icons', ids: ['1:2', '1:3'] }
```

来源仍需填写文件并配置认证。`ids` 限定发给 Figma 的读取范围，最终同步结果还受 depth、pages、命名 hook 与节点树解析影响。插件不会自动修改来源配置，也不保证最终导入集合严格等于所复制的列表。

切换复制内容会清除旧反馈和手动文本，但不会解除尚未结束的剪贴板写入锁。请等待原生写入结束后再显式复制新内容；已开始的写入仍可能写入当时捕获的文本。权限受限时，使用当前模式的只读 JSON 与 **Select JSON** 手动复制。切换内容不会取消 Locate 或批选、提交任务、改变连接模式、发送宿主／网络消息或保存偏好。整页报告与 SVG 导出保持原范围。重新构建插件即可，无需更新服务端。

## 导出原始 SVG 交接包

点击 **Export SVG ZIP**，导出当前页的全部非草稿组件。插件先用已加载规则重新预检整页；搜索、Problems only、Issue type 和当前选择不会缩小导出范围。所有图标通过预检且原生导出全部成功后才下载。失败会显示对应节点，不下载部分内容；修复后可重新导出。已配对项目使用确认过的项目规则，GitHub 与未配对模式沿用各自默认规则；项目规则不可用时先刷新。配置了服务端命名 hook 的项目需先同步到控制台，再下载确认过的快照。

ZIP 只含 `raw-svg/<图标名>.svg`，组件集变体按标准规则命名。这些是 Figma 原始 SVG，尚未经过 iconctl 优化、`currentColor` 转换和服务端命名。Figma 导出完整组件边界，将文字转为轮廓，保留文档色彩配置与默认描边简化。文件名必须是可移植的 ASCII 名称；`con` 等保留名与超过 240 字符的完整路径会明确拒绝，不自动改名。最多 5000 个 SVG，单文件 1 MiB、SVG 内容合计 5 MiB、最终 ZIP 8 MiB，任何超限均取消整个导出。

将 ZIP 解压到工程目录，输入与生成目录分别保存。例如在 `raw-svg/` 旁创建 `iconctl.config.ts`：

```ts
import { defineConfig } from '@iconctl/core'

export default defineConfig({
  prefix: 'design',
  sources: [{ type: 'directory', dir: 'raw-svg' }],
  output: {
    json: 'icons.json',
    svg: 'svg',
    types: 'icons.d.ts',
    preview: 'preview.html',
  },
})
```

```bash
pnpm exec iconctl sync --dry-run
pnpm exec iconctl watch
```

收到新版 ZIP 后，只替换本交接包所属的输入目录，避免已删除图标残留。工程配置应采用项目所需的尺寸校验。此 ZIP 也可交给现有 runner 的 SVG ZIP 来源，使用 `dir: 'raw-svg'`。

即使 Live preflight 关闭，本次导出也会临时监听页面编辑。收到编辑事件、切页、切换模式或项目、手动 Rescan、刷新规则、Cancel 或关闭插件均使导出失效。Figma 当前原生导出无法强制中断；取消会停止后续组件并丢弃结果，等待进行中的操作结束后才允许重试。这是通过页面事件和节点复核保护的交接操作，不是 Figma 原子文档快照。导出不请求网络、不写存储、不创建任务，也不自动同步；已有任务继续跟踪，并保留独立反馈。重新构建插件即可使用，无需升级控制台或迁移数据。
