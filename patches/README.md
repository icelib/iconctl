# Maintained dependency patches

`readdirp@5.1.1.patch` treats `ENOTDIR` like a directory that disappeared during traversal. A directory can be replaced by a file between Chokidar’s stat and readdir. Without this classification readdirp destroys its stream, while Chokidar 5 suppresses the error and awaits an end event that never arrives. The application then waits indefinitely for readiness.

The patch is generated and registered by `pnpm patch` / `pnpm patch-commit`. Keep its exact version and lockfile hash; do not change installed dependency files or suppress unused-patch failures. A future dependency update must verify this race before removing the patch.

Core bundles Chokidar and readdirp because package consumers do not inherit workspace patch settings. Both module entry points load that same implementation; CommonJS uses synchronous `require(ESM)` on the existing Node.js >=22.13 baseline. The included `THIRD_PARTY_NOTICES` preserves both dependency licenses.

Run `pnpm --filter @iconctl/core test:package` to build and pack the actual core and CLI, install them with npm in a temporary consumer, and verify native ESM/CJS resolution, declarations, exported identities, watcher startup/replacement/recreation/cancellation, and CLI signal shutdown. A separate package with the former external dependency boundary must still reproduce the ENOTDIR readiness hang. The script deletes only its own temporary fixture and uses no registry publication, global installation, workspace links, or consumer patch policy. It requires registry access to install normal consumer dependencies. To repeat with a specific existing Node executable, run the script after building with `node packages/core/scripts/test-watch-package.mjs /absolute/path/to/node`.

`Package consumer CI` runs this check on Linux with Node 22 and 24. Source-level startup and handover regressions live in `packages/core/test/watch-enotdir.test.ts`; the existing watcher suites cover broader lifecycle behavior.

`@icebreakers__monorepo@6.0.1.patch` keeps repoctl nightly consumer verification compatible with the pinned pnpm 12.6.0. That pnpm version emits JSON progress but a formatted fatal diagnostic even with `--reporter=ndjson`. After a successful npm upload, a temporarily missing installation packument therefore bypassed repoctl's bounded installation retry.

The patch recognizes only the observed missing-version diagnostic for an exact package/tag or package/version from the confirmed batch and the official npm registry. It also freezes each verified previous nightly identity before uploading. If an otherwise successful installation still resolves that exact previous identity, it retries installation within the same visibility budget; unknown versions or conflicting identities fail immediately. Unknown text, conflicting errors, authentication failures, and integrity failures still stop immediately. It retains repoctl's visibility timeout and subsequent identity/export/type checks; it never republishes a confirmed upload.

Each attempt writes its cache directory into the isolated `pnpm-workspace.yaml`. pnpm 12.6's Rust installer ignores the former `--config.cache-dir` flag, even though its compatibility `config get` command echoes it. Changing that flag did not isolate the metadata cache, so retrying could keep installing an old tag after npm had accepted the new publication. The store and state directories remain isolated as well. The workspace grants `minimumReleaseAgeExclude` only to the exact confirmed package versions, allowing a newly published nightly to be tested while keeping the default age policy for other versions and dependencies. Rewriting this file also clears any automatic age exceptions pnpm persisted during a previous attempt. Remove the patch only when an upstream repoctl release covers these pnpm 12.6 boundaries and the regression suite passes.

The workspace is serialized as block-style YAML with the dependency's existing YAML library. pnpm can read multi-line JSON as YAML but cannot append its automatic age exceptions to that flow collection. Keep the block format editable so a dependency with only a recent version follows pnpm's normal policy without failing the installation.

`pnpm run test:automation` tests the installed patched dependency, including the captured pnpm 12 diagnostics, successful installs resolving previous tags, frozen identity boundaries, unrelated failures, state isolation, and bounded retries. A local HTTP registry fixture runs the real pinned pnpm installer against tiny tarballs to verify fresh metadata requests, exact publication-age exceptions, and retained dependency age checks. These tests deliberately load the pinned bundle's private consumer regions because repoctl does not expose them as a public API; an upstream layout change requires an explicit patch review.
